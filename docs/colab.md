# Colab版73Botの使い方

## 必要なもの

- GPUを利用できるGoogle Colab。Python 3.12を想定しています。
- Google Driveの空き容量。モデルの重みと参照音声、試聴レポートを保存します。
- 自分の録音。書き起こしは任意です。入力する場合、ITAコーパスの録音なら該当する文章を照合してください。
- Discord Developer Portalで作成したBOTのトークン。

初版のモデルは `Qwen/Qwen3-TTS-12Hz-0.6B-Base` のみです。自動で別モデルやCPUへ切り替えません。
無料ColabのGPU割り当てや実行時間は保証されません。必要なときに手動起動する検証用として扱い、
自動クリックや切断回避は行いません。[Colab公式FAQ](https://research.google.com/colaboratory/faq.html)

## Discordの準備

1. Developer Portalの対象アプリでBotを作成し、**Message Content Intent**を有効にします。
2. OAuth2の招待に `bot` と `applications.commands` を指定します。
3. BOTに対象チャンネルの閲覧・メッセージ送信・VCへの接続・発言を許可します。チャンネル個別の上書き権限も確認します。
4. 同じトークンを使っている別のBOTプロセスがあれば停止します。
5. Colab左側の鍵アイコン「シークレット」に `DISCORD_BOT_TOKEN` を追加し、ノートブックのアクセスを許可します。

トークンはセル・Drive設定・音声プリセット・Gitに保存しません。起動プロセスにのみ渡され、音声ワーカーへは継承しません。
起動時のコマンド同期は、このBOTアプリのグローバルコマンドをColab版の5種類に置き換えます。旧 `/voice` は削除されます。

## ノートブックを開く

[Colabでノートブックを開く](https://colab.research.google.com/github/Gai-b63a/73Bot/blob/master/notebooks/73Bot_Colab.ipynb)から自分のDriveにコピーし、GPUランタイムを選びます。
ダウンロードした `notebooks/73Bot_Colab.ipynb` をColabにアップロードしても使えます。
Pythonのバージョンが3.12以外なら、Colabの「過去のランタイム」から対応版（例: 2026.07）を選びます。
[ランタイムの公式情報](https://research.google.com/colaboratory/runtime-version-faq.html)

最初のセルは既定のGitHubリポジトリの `master` からコードを取得します。別の版を試すときは `REVISION` にブランチ名またはコミットを指定します。
GitHubへ反映する前の変更を使う場合は、[開発手順](../CONTRIBUTING.md#ノートブックとzipの更新)に従って配布ZIPを作成します。
ZIPをDriveの `MyDrive/73Bot/73Bot_Colab.zip` に一度保存し、最初のセルの `SOURCE` を「DriveのZIP」に変更してください。
コードもDriveから復元するため、次回の再アップロードは不要です。別の場所へ保存した場合は `ZIP_PATH` を変更します。

ノートブック自体はDriveの任意のフォルダに置けます。ルートに置く必要はありません。
録音・設定の保存先は `STORE_ROOT`、ZIPの場所は `ZIP_PATH` で別々に指定します。
`73Bot` と `73BOT` のように、パスの大文字・小文字も実際のフォルダ名に合わせてください。

セットアップは専用のPython環境を作り、Colab標準のtorch/torchaudioを利用します。
Qwenの依存ライブラリをノートブックのカーネルと分離するため、通常はカーネル再起動が不要です。
セットアップやコード取得セルは、BOTや試聴を停止してから再実行してください。

## 初回：声を登録する

1. Drive接続セルを実行します。既定の保存先は `MyDrive/73Bot` です。
2. 管理画面でDrive上の録音パスを入力するか、「音声を選ぶ」でファイルをアップロードします。
3. 見本にする区間の開始・終了秒を指定します。ノイズや言い直しの少ない5〜15秒が目安です。受付範囲は3〜30秒です。
4. 声の名前を入力し「声をDriveに登録」を押します。書き起こしは空欄で構いません。入力する場合は、その区間で話している文章と一致させます。
5. 登録した声を選び「設定を保存」。試聴する文章を入力して「試聴」を押します。
6. 「状態・ログを確認」で終了を確認し、生成音声を聞きます。試聴が終了してからBOTを起動します。

登録時は選択区間をモノラル24kHz WAVに変換します。元の録音ファイルは変更しません。
同じ名前を再登録しても既存のプリセットは上書きせず、別IDとして保存します。
プリセットにモデル名は含めず、参照音声と任意の書き起こしを保存します。モデル設定は別ファイルです。

書き起こしが空欄の場合は、同じQwenモデルの `x_vector_only_mode` で声の特徴だけを使います。
入力がある場合は録音と文章を利用する従来の方式です。空白だけの入力も空欄として扱います。
公式では録音だけの方式は声の再現品質が下がる可能性があるとされているため、登録後に試聴してください。
[Qwen公式の方式説明](https://github.com/QwenLM/Qwen3-TTS#voice-clone)
保存済みの書き起こし付きプリセットはそのまま使えます。録音だけの方式で試したい場合は、同じ録音を書き起こし空欄で別のプリセットとして登録します。

## 通常起動と声の変更

新しいColabセッションではセットアップ・Drive接続を行い、保存済みの声を確認して「BOTを起動」を押します。
初回はモデルのダウンロード、以後も一時ディスクへのコピーとウォームアップに時間がかかります。
重みは初回に解決したHugging Faceコミットに固定して再利用します。

準備完了後にDiscordでVCへ入り、読みたいテキストチャンネルで `/join` を実行します。
声の変更は「停止 → 声を選択 → 設定を保存 → BOTを起動」です。Discord利用者は声を変更できません。
Colabで稼働中に「管理画面」セルだけを再実行しても同じプロセスを管理します。

| コマンド | 動作 |
|---|---|
| `/join` | 実行したテキストチャンネルの監視を開始。接続済みの場合は同じVCから監視先を変更可能 |
| `/leave` | 現在の読み上げと待ち行列を終了して退出 |
| `/skip` | 現在の投稿の残りを飛ばす。進行中の計算結果は破棄 |
| `/clear` | 未再生の投稿のみを消す。現在の投稿の残りは読み続ける |
| `/status` | 声、接続、待ち件数、音声生成状態を表示 |

再生操作はBOTと同じVCの参加者のみ行えます。別VCからBOTを移動させることはできません。
各サーバーで1つのVCと監視テキストチャンネルに対応し、全サーバーで同じ声と1つのGPUワーカーを共有します。
人がいなくなると退出します。再起動後は `/join` をやり直します。

## 読み上げの扱い

- 投稿順を守り、新しい投稿によって再生を中断しません。句読点優先で最大40文字に分割します。
- 再生中に次の区間を生成し、先読みは1区間まで。独自の音声ストリーミング実装は使用しません。
- 5秒を超えても読み上げます。1区間の生成が60秒を超えた場合、GPUメモリ不足、ワーカー異常終了は読み上げを停止します。
- その場合はColabのログを確認し、停止してから再起動します。他モデルや別の声へ勝手に切り替えません。
- 待ち行列はサーバーごとに最大100投稿。満杯のときは新しい投稿を受付せず、30秒に1回まで通知します。
- URLは「URL」、メンションは表示名。コードブロックは省略します。DM・BOT投稿・本文なしの投稿は読みません。
- 辞書は `{"73Bot": "ななみボット", "HP": "エイチピー"}` のようなJSON形式。長い一致から一度だけ置換します。

## 測定と合格の判断

実装時のローカルGPU試験では、書き起こしありで短文3例の生成に5.2〜15.2秒、なしで8.5〜16.8秒かかり、5秒目標は未達でした。
Colab・本人の声・Discordでの実測は別途必要です。[検証記録](validation.md)

「20例×3回の測定」はウォームアップ後、短文・数字・固有名詞・日英混在の固定20例を3回生成します。
60個の音声と個別の測定値、平均・95パーセンタイル・最大・GPUピークメモリが `reports/<実行ID>/benchmark` に保存されます。
生成した各音声を聞いて、元の声との似方、読み間違い、読み飛ばし、繰り返し、抑揚を確認してください。

BOT実行では次を別々に測ります。

- `idle_first_packet_seconds`: 接続済み・待ち行列なし・GPU待ちなしで受信した投稿から、最初の音声パケット送信成功まで。
- `queued_first_packet_seconds`: 他の投稿の再生・生成待ちがあった場合。前の読み上げ待ちを含みます。
- `generation_seconds`: 各区間の生成とDiscord用PCM変換にかかった時間。

集計結果は `summary.json`、個別記録は `events.jsonl`。通常投稿の本文・参照音声の書き起こし・トークンは記録しません。
環境情報の `reference_mode` は `audio_only`（録音のみ）または `audio_and_transcript`（書き起こしあり）です。
**5秒を超えた回があれば `all_within_5s: false`、測定がなければ `null`** です。未測定や平均だけで達成と判定しません。
送信開始時刻は受信側の再生バッファを含まないため、実際の聞こえ始めもVCで確認します。
停止時にレポートをDriveへコピーします。セッションを強制削除した場合、未保存のレポートは失われることがあります。

## トラブル時

- **GPUなし**: ランタイムをGPUへ変更。無料枠で割り当てられない場合は後で再試行します。
- **トークンなし**: シークレット名とノートブックアクセス許可を確認します。
- **声未指定・録音なし**: プリセットを登録・選択し、設定を保存します。
- **二重起動の表示**: 先に「停止」。試聴・測定・BOTは同時に実行できません。
- **VC接続失敗**: Message Content Intent、接続・発言権限、Colabセットアップの完了を確認します。
- **メモリ不足・タイムアウト**: 停止して再起動。改善しない場合は測定結果とGPU名を確認し、速度目標は未達として扱います。
- **Drive容量不足**: 保存に必要な容量を確保して再試行します。モデルキャッシュは自動削除しません。
